One row, one case, four backends

The saver contract has five methods. Each row below is one case of the reference checkpoint-conformance inventory, read from one pinned commit (e5e37b5d70db) rather than from a moving branch. Each names the assertion in integration/src/conformance.mbt that exercises it, and each of those assertions runs on memory, sqlite, postgresql, mysql with the same expected value.

92 reference cases, plus one the suite does not name, make 93 rows in total. A row whose note says a concept is absent names the equivalent observable behaviour: this contract has no channel versions, metadata filters, namespaces beyond the thread id, or prune strategies. It stores whole states, filters pages by before and limit, and deletes a thread as one unit. Those differences are listed in the Conformance section of the README.

The registry is pinned too

Span names are checked against a semantic-convention registry at one pinned commit, e6658f14c9d9ea0760825f029cb82e7673f48fab, recorded in scripts/weaver_registry_pin.txt. A check that follows a default branch can turn red on a change nobody in this repository made.
