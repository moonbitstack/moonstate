One row, one case, four backends

The saver contract has five methods. Each row below is one case of the reference checkpoint-conformance inventory, read from one pinned commit () rather than from a moving branch. Each names the assertion in integration/src/conformance.mbt that exercises it, and each of those assertions runs on with the same expected value.

reference cases, plus one the suite does not name, make rows in total. A row whose note says a concept is absent names the equivalent observable behaviour: this contract has no channel versions, metadata filters, namespaces beyond the thread id, or prune strategies. It stores whole states, filters pages by before and limit, and deletes a thread as one unit. Those differences are listed in the Conformance section of the README.

The registry is pinned too

Span names are checked against a semantic-convention registry at one pinned commit, , recorded in scripts/weaver_registry_pin.txt. A check that follows a default branch can turn red on a change nobody in this repository made.
