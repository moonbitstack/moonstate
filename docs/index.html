Durable state graphs, and nothing else

A run is a sequence of supersteps. In each one a set of nodes runs, each returns the updates it wants applied, and the updates fold into the state in task order. Before every superstep is written a checkpoint. When a process dies, the next run opens the last checkpoint and continues; when a node asks a question, the run stops and waits.

The ring is that run. Its phases are the supersteps the graph may take — twenty-five of them by default. The arc is the supersteps that ran; the notches are the checkpoints they left. Everything on this page is the library, compiled to JavaScript and running in your tab: the state, the checkpoint ids and the numbers are read from it, not drawn by the page.

Nothing here is a recording. Press Run, then press Pull the plug at any stop: the tab reloads, and the run is where you left it, because the checkpoint is a record and this page keeps the records.

Every stop is a checkpoint

A checkpoint is the state as merged, the tasks the next superstep will run, and whether the run is waiting on an answer. Pick one below to read it — that is the history the saver hands back, newest last.

    A question is a stop, not a callback

    A node returns Interrupt(payload) and the run ends there, with the payload in the checkpoint. Nothing is held in memory: the answer arrives later, from anywhere, and the node that asked runs again and reads it.

    Switch to a question and press Run. The ring stops one phase in, the arc goes dark, and a number is wanted. Answer it — then answer it after a reload, which is the same path a server takes after a restart.

    Three writes, one fold

    Send queues a node once per input, and the three of them run in one superstep. Their writes fold into the state in the order the tasks were queued, which is why the result does not depend on which one finished first. Switch to a fan-out: three shards add one each, and the log keeps their order.

    Time travel is a write

    A finished thread can be taken back: update writes a state as if a node had produced it, then the run continues from what follows that node. The checkpoints of the abandoned attempt stay in the history — the ring keeps both arcs.

    On a line, run it to the end and press Rewrite the tail.
